# Assumptions

| ID | Assumption | Why I needed it | Impact if it is wrong |
|---|---|---|---|
| **AS-01** | **In-Region Cache Latency:** Azure Cache for Redis hosted in the same Azure VNet provides p95 read latency < 5 ms for rating table lookups. | Essential to decouple quote latency from Salesforce backend load and guarantee C2 (< 2.5s p95). | If latency is higher (> 50 ms), rating tables would need to be cached in-memory directly on individual Container App replicas, requiring local memory sizing and multi-instance cache invalidation. |
| **AS-02** | **Salesforce Core Apex Rating API Interface:** The `sf-policy-sapi` rating endpoint can accept an explicit `ratingTableVersion` identifier in the calculation payload to ensure consistency. | Needed to ensure that ratings calculated against cached tables match the historical table version recorded in Salesforce. | If Salesforce Core only rates against live active tables in the org, rating engine logic must be duplicated or ported into the MuleSoft Process API layer. |
| **AS-03** | **Platform Team Developer Loan Approval:** The Salesforce Platform Team will formally approve lending 1 MuleSoft developer for 6 weeks in Q1 2027 upon formal request prior to 15 December 2026. | Required to deliver the unified `home-quote-papi` and resolve technical debt TD-01 without delaying the Mexico launch on 30 April 2027. | If denied, we must redirect 6 person-weeks from Nimbus (contingent on contract renegotiation) or defer Chilean and Colombian refactoring to Q2. |
| **AS-04** | **Nimbus Contract Renewal Acceptance:** Nimbus Digital will accept the technical governance terms (Azure Pipelines, PR gates, Meridian Tech Lead sign-off) in their contract renewal on 31 January 2027. | Necessary to eliminate vendor silos, retire unmonitored deployments, and unify the `channel-bff` codebase. | If Nimbus refuses, Meridian must either transition maintenance to internal staff or prepare an RFP to replace the vendor, which would impact delivery timelines. |
| **AS-05** | **Asynchronous Policy Issuance Compliance:** Insurance superintendencies in Mexico (CNSF), Colombia (SFC), and Chile (CMF) permit issuing the official policy document asynchronously within 3 minutes of customer payment. | Allows the quote-and-buy web journey to show an immediate on-screen binding confirmation, shielding the customer from Salesforce issuance latency (1.8s–4.0s) and downtime. | If synchronous document delivery is legally mandated, customer checkout latency will increase to ~4.5 s and will be vulnerable to Salesforce 3% downtime. |
| **AS-06** | **OIDC Claims Availability:** The enterprise Identity Provider team can reliably populate `ctry` and `sf_account_id` in customer JWT tokens without requiring real-time external database lookups during token issuance. | Critical to enforce tenant isolation and zero-trust authorization in `channel-bff` and `quote-xapi` without trusting client HTTP headers. | If claims are unavailable in tokens, the BFF would need to look up country binding upon initial session creation, adding one database roundtrip. |
| **AS-07** | **Salesforce API Allocation Buffer Availability:** The Salesforce Platform Team can grant emergency temporary quota increases (e.g. +500,000 calls) within 2 hours during critical incident escalations. | Serves as a last-resort safety valve during unprecedented commercial surge events. | If temporary quota increases are unavailable, the channel must enforce hard client-side rate shedding to protect payment processing. |
| **AS-08** | **Azure Container Apps Quota:** Meridian's primary Azure production subscription has sufficient core quota to run dedicated container scale groups for `channel-bff-mx`, `channel-bff-co`, and `channel-bff-cl`. | Required to establish physical runtime bulkheads per country without shared resource contention. | If subscription quota is restricted, namespace or node pool resource quotas in Azure Kubernetes Service (AKS) would be required. |
